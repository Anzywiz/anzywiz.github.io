04 — File format & delimiters

How the data is structured

The output is a flat .txt file. Two separator characters are used at different levels.

File format
Plain text (.txt), one row per product-color variant, UTF-8 encoded
Column separator
; (semicolon) — separates every field in the row
Multi-value separator
| (pipe) — used within a field when that field holds multiple items
Fields using |
all_images — pipe-separated list of image URLs
additional_content → availability_id sub-field — pipe-separated per-size availability counts
additional_content → is_consignment sub-field — pipe-separated yes/no per size
String cap
All string columns capped at 1,000 chars to comply with validator constraints
Price cap
Prices capped at 99,999,999.99 — matches DBQ validator type NUMERIC(10,2). Values exceeding this are nulled (13 rows affected in latest delivery).
Date format
YYYY-MM-DD for competence_date and promotion_end_date

Example — all_images field:
https://fdcdn.akamaized.net/.../res_940599d3.jpg|https://fdcdn.akamaized.net/.../res_9f5f6286.jpg
Each URL separated by | — split on pipe to get the full image list per variant.

07 — Improvement opportunities

What could be added

Fields that exist on fashiondays.ro but aren't yet collected.

Easy
size_info
Available sizes are shown per product listing (e.g. 36, 37, 38…). Currently not captured. Could be scraped in a single pass from existing product pages.
Easy
material_info
Fabric composition (e.g. "100% cotton", "piele naturală") is listed in the product details accordion on most items. Visible on the same page — one additional selector.
Easy
promotion_end_date (coverage)
Currently at 8.2% fill — the field exists and is being collected, but only populated when a countdown timer is visible on the page. Broader date parsing could improve coverage.
Medium
delivery
Estimated delivery timeframe shown at checkout or in the product detail sidebar. Requires following a deeper page-level interaction or a secondary request per product.
Medium
quantity / size-level stock
The availability_id sub-field in additional_content already captures per-size availability codes (e.g. 5 | 3 | 3 | 5 | 5). Mapping these codes to labeled sizes would elevate this to a proper per-size stock field.
Hard
price_eur (normalised)
EUR-equivalent price is already captured inside additional_content as a JSON sub-field. Promoting it to a top-level column would make cross-currency comparison instant without JSON parsing on the buyer's side.
Note on pricing: fashiondays.ro is a multi-merchant marketplace with active promotions. Both price (current selling price) and full_price (pre-discount RRP) are collected and will differ whenever a promotion is active. The discount percentage is also delivered in promotion_type.
